# 扫雷网页版 — 需求规格说明书（SRS）

> 文档编号：SRS-01 ｜ 版本：1.0 ｜ 状态：已评审（用户确认）
> 开发方式：SDD（Specification-Driven Development，规范驱动开发）

---

## 1. 项目概述

### 1.1 项目名称
网页版扫雷（Minesweeper Web）

### 1.2 项目目标
实现一个可在浏览器中直接运行、无需安装依赖与构建步骤的经典扫雷游戏，界面为中文，采用现代视觉风格（圆角、渐变、动画）。

### 1.3 技术约束（来自用户确认）
- **技术栈**：原生 HTML / CSS / JavaScript，单页面应用，无构建工具，零外部依赖。
- **界面语言**：中文。
- **体验风格**：现代美化（圆角 / 渐变 / 动画），不做深色模式。
- **音效**：使用 Web Audio API 程序化合成（零外部音频文件、零依赖）；范围包括点击/插旗轻音效、胜利喜庆音效、踩雷遗憾音效，并提供静音开关。
- **范围排除**：不做最佳成绩持久化（不使用 localStorage）、不做联网功能、静音偏好仅保存在内存中（刷新即恢复默认开启）。

## 2. 术语表

| 术语 | 含义 |
| --- | --- |
| 格子（Cell） | 棋盘上的一个单元，坐标为 (row, col) |
| 雷（Mine） | 埋藏在棋盘中的炸弹 |
| 旗（Flag） | 玩家标记疑似雷的标记 |
| 问号（Question） | 玩家标记不确定的标记 |
| 数字格 | 已翻开且显示周围 8 邻域雷数的格子 |
| 洪泛展开（Flood Fill） | 翻开数字为 0 的格子时，递归展开周围区域直至遇到数字边界 |
| Chord（双击展开） | 对已翻开的数字格，当其周围旗数等于自身数字时，翻开周围所有未标记格子 |
| 剩余雷数 | 总雷数 − 旗数，允许为负数 |
| 首击安全 | 首次左键点击的格子及其 3×3 邻域（含自身）绝不出现雷 |

## 3. 功能需求（FR）

### FR-01 棋盘生成
- 系统按当前难度生成 `rows × cols` 的矩形棋盘，共埋藏 `mines` 个雷。
- 雷的分布要求随机，且在首击之前不实际布雷（见 FR-03）。

### FR-02 难度等级
| 难度 | 行数 rows | 列数 cols | 雷数 mines |
| --- | --- | --- | --- |
| 初级 | 9 | 9 | 10 |
| 中级 | 16 | 16 | 40 |
| 高级 | 30 | 16 | 99 |
| 自定义 | 9 ~ 40 | 9 ~ 60 | 1 ~ (rows×cols − 9) |

- 自定义范围约束：
  - `rows`：9 ~ 40（含）
  - `cols`：9 ~ 60（含）
  - `mines`：1 ~ `rows × cols − 9`（保证首击安全的 9 格可用空间）
  - 超出范围时给出中文提示并拒绝应用。

### FR-03 首击安全
- 首次左键点击的格子 `(r, c)` 及其 8 邻域（共最多 9 个格子）中不允许存在雷。
- 实际布雷发生在首次左键点击之后：从**排除上述 9 格**的剩余格子中随机选取 `mines` 个作为雷。
- 首击同时触发计时器启动（见 FR-09）。

### FR-04 左键翻开
- 左键点击**未翻开且无旗标记**的格子：
  - 若该格为雷 → 游戏失败（见 FR-08）。
  - 若该格数字为 0 → 触发洪泛展开（见 FR-05）。
  - 否则翻开该格并显示邻雷数字（无雷且非 0 时不显示数字，即空白）。
- 左键点击**旗标记**的格子：不产生任何效果。
- 左键点击**问号标记**的格子：按未标记格子处理，可被翻开。

### FR-05 洪泛展开
- 翻开数字为 0 的格子后，递归展开其 8 邻域：
  - 遇数字格（邻雷数 > 0）→ 翻开并停止向内传播；
  - 遇 0 格 → 翻开并继续向外传播；
  - 遇旗格 → 跳过不展开（旗格不参与洪泛）。
- 洪泛展开期间若误展开到雷（仅在旗标记错误的场景下可能），按踩雷判负。

### FR-06 右键标记
- 右键点击**未翻开**的格子，标记状态按循环切换：`无标记 → 旗 → 问号 → 无标记`。
- 旗标记的格子不可被左键翻开（见 FR-04）。
- 已翻开的格子右键无效。
- 每插一面旗，剩余雷数减 1；取消旗则加 1；问号不影响剩余雷数。

### FR-07 Chord（双击快速展开）
- 左键点击**已翻开且数字 > 0** 的格子：
  - 若其周围旗数量等于其数字 → 自动翻开周围所有**未标记**的格子（含问号格）。
  - 若旗数量不等于其数字 → 不产生任何效果。
- 自动翻开过程中若命中雷（旗标记错误导致）→ 判负（见 FR-08）。

### FR-08 胜负判定
- **失败**：翻开任意一个雷。
  - 触发时：停止计时；所有雷以红色高亮显示；被错误插旗的非雷格以红叉样式标出；点错的雷格高亮。
- **胜利**：所有非雷格子全部翻开（`已翻开数 == rows × cols − mines`）。
  - 触发时：停止计时；自动为未标记的雷格补上旗；显示胜利状态。
- 终态（won / lost）下棋盘不再响应翻开与标记操作，仅可重开（见 FR-12）。

### FR-09 计时器
- 状态：未开始（显示 `000`）、进行中（计时）、结束（定格）。
- 首次左键点击后开始计时；胜利或失败时停止。
- 显示格式：`mm:ss`（分钟不足两位补零；上限 99:59）。
- 计时基于系统时间差计算，不允许因 `setInterval` 漂移而失真。

### FR-10 剩余雷数
- 状态栏显示 `剩余雷数 = mines − 旗数`，可为负数（负数前显示 `-`）。
- 格式为三位数字显示（如 `010`、`-3` 显示为 `-03`）。

### FR-11 状态表情
- 状态栏中央显示游戏状态表情：
  - 未开始 / 进行中：😊
  - 胜利：😎
  - 失败：😵
- 点击表情按钮：重新开始当前难度的游戏。

### FR-12 重新开始与难度切换
- 任意时刻点击表情按钮或切换难度，均立即以目标难度重新生成棋盘并复位所有状态（计时、标记、展开）。

### FR-13 自定义难度对话框
- 提供"自定义"入口，弹出对话框，包含：行数、列数、雷数三个输入框及"确定 / 取消"按钮。
- 校验规则见 FR-02；非法输入时显示中文错误提示，不关闭对话框。
- 确定后应用自定义难度并重开游戏。

### FR-14 音效
- 音效由 Web Audio API 程序化合成，**不引入任何外部音频文件**（保持零依赖约束）。
- 各场景音效：
  | 场景 | 触发时机 | 音效要求 |
  | --- | --- | --- |
  | 点击 | 每次左键翻开 / Chord 动作成功执行 | 极短促的轻"嗒"声，音量低，不打扰 |
  | 插旗/标记 | 每次右键标记状态发生切换 | 短促的轻"啵"声（与点击声可区分） |
  | 胜利 | 达成胜利条件时 | 喜庆上行琶音（如 C5-E5-G5-C6），明亮、渐强收尾 |
  | 失败（踩雷） | 翻开雷时 | 遗憾下行滑音（三连下坠），低沉、缓慢 |
- 胜利 / 失败音效与状态表情切换同时触发；终态时不再播放点击 / 标记音效。

### FR-15 静音开关
- 界面提供音效开关按钮（图标 🔊 / 🔇 切换，标题提示"音效：开/关"）。
- 静音状态下所有音效（含点击 / 标记 / 胜利 / 失败）均不发声。
- 静音偏好仅保存在内存中，**不持久化**（刷新页面后恢复默认开启）。
- 首次点击格子时初始化音频上下文（浏览器自动播放策略要求：音频只能在用户手势后启动）。

## 4. 非功能需求（NFR）

| 编号 | 需求 |
| --- | --- |
| NFR-01 | 零依赖、无构建：双击 `index.html` 即可在浏览器中运行 |
| NFR-02 | 界面全部为中文 |
| NFR-03 | 兼容现代浏览器（Chrome / Edge / Firefox / Safari 近两个大版本） |
| NFR-04 | 性能：最大棋盘 60×40=2400 格下操作无卡顿；渲染不低于 60fps |
| NFR-05 | 可维护性：核心游戏逻辑（core）与视图（ui）分离；core 为纯逻辑模块，不依赖 DOM，可在 Node 中独立测试 |
| NFR-06 | 棋盘整体尺寸自适应：不超过视口 85% 高度/宽度，格子随棋局规模自动缩放 |
| NFR-07 | 不收集、不发送任何用户数据；无外部请求 |
