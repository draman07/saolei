## 1. 系统架构

### 1.1 分层结构
```
┌─────────────────────────────────────────────┐
│  HTML (index.html)  +  CSS (css/style.css)   │  展示层
├─────────────────────────────────────────────┤
│  js/ui.js          视图层：渲染、事件、动画   │
├─────────────────────────────────────────────┤
│  js/audio.js       音效层：Web Audio 合成     │
├─────────────────────────────────────────────┤
│  js/core.js        逻辑层：纯游戏逻辑（无 DOM）│
├─────────────────────────────────────────────┤
│  js/config.js      配置层：难度参数           │
└─────────────────────────────────────────────┘
```

### 1.2 依赖方向
- `ui.js` → `core.js`、`config.js`、`audio.js`（单向依赖，禁止反向引用）。
- `core.js` 不得引用 `document` / `window` / `localStorage` 等浏览器 API，保证可在 Node 中直接加载测试。
- `audio.js` 仅依赖 `window.AudioContext`（懒初始化，测试可注入 mock），不依赖 core。
- 页面按 `config.js → core.js → audio.js → ui.js` 顺序以普通 `<script>` 标签加载，无模块打包器。

### 1.3 模块导出方式
- `config.js`：暴露全局 `window.MINESWEEPER_CONFIG`（仅浏览器使用，不参与 Node 测试）。
- `core.js`：采用 UMD 风格导出——浏览器中挂载到 `window.MINESWEEPER_CORE`；Node 中通过 `module.exports` 导出，便于自动化验收测试。
- `audio.js`：UMD 风格，浏览器挂载 `window.MINESWEEPER_AUDIO`，Node 中 `module.exports`（便于测试评分数据与静音逻辑）。
- `ui.js`：挂载 `window.MINESWEEPER_UI`，浏览器启动入口 `init()`。

### 1.4 目录结构
```
code/
├── index.html              页面骨架
├── css/style.css           全部样式与动画
├── js/config.js            难度配置
├── js/core.js              核心逻辑（UMD）
├── js/audio.js             音效合成（UMD，Web Audio）
├── js/ui.js                视图层
├── specs/                  规范文档（SRS/SDS/ATS）
└── tests/acceptance.test.js Node 自动化验收测试
```

## 2. 数据模型

### 2.1 格子（Cell）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| row | number | 行号，0 起 |
| col | number | 列号，0 起 |
| isMine | boolean | 是否为雷（首击前全部为 false，见 3.1） |
| neighborMines | number | 8 邻域雷数（布雷完成后计算） |
| state | 'hidden' \| 'revealed' \| 'flagged' \| 'question' | 展示状态 |

### 2.2 游戏状态（GameState）
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| rows / cols / mines | number | 棋盘规模（不可变，重开时重建） |
| board | Cell[][] | 二维格子数组，索引 `[row][col]` |
| status | 'ready' \| 'playing' \| 'won' \| 'lost' | 状态机状态（见 2.3） |
| flagCount | number | 当前旗数 |
| revealedCount | number | 已翻开非雷格数 |
| firstClick | { row, col } \| null | 首次点击坐标 |
| timer | { started, startTime, stoppedAt } | started：是否已首击；startTime：首击时间戳；stoppedAt：终局定格时间戳（null 为进行中） |

### 2.3 状态机
```
           左键首击（布雷+起表）
  ready ────────────────────────► playing
                                   │  ├── 翻开雷 ──► lost
                                   │  └── 全部非雷翻开 ──► won
  ready / playing / won / lost ── 重开（表情/难度/自定义）──► ready
```
- `won` / `lost` 为终态：所有格子输入事件失效，仅保留重开入口。

## 3. 核心算法规格

### 3.1 布雷（首击后执行）
1. 输入：`rows, cols, mines, firstClick = (r, c)`。
2. 构建禁区集合 `excluded` = 以 `(r, c)` 为中心的 3×3 邻域（越界裁剪）。
3. 候选集 = 全部格子 − excluded；若 `mines > 候选集大小`，抛出配置错误（正常配置不会触发）。
4. 从候选集中**随机无放回**抽取 `mines` 个置为雷。
5. 随机源：`Math.random()`；为可测性，`createGame` 接受可注入的随机函数 `rng`（默认 `Math.random`）。
6. 布雷完成后计算每个格子的 `neighborMines`（8 邻域计数）。

### 3.2 翻开（reveal）
```
输入 (r, c)
1. 若 status 为终态 或 格子已翻开 或 格子为旗 → 无操作返回
2. 若 status === 'ready'（首击）：
     a. 执行布雷(3.1)，status → 'playing'，启动计时
3. 若格子是雷：
     a. status → 'lost'，停止计时
     b. 记录踩雷格（供 UI 高亮）
     c. 返回失败事件
4. 否则：
     a. 格子 state → 'revealed'，revealedCount++
     b. 若 neighborMines === 0 → BFS 洪泛（队列，8 邻域）：
        - 遇旗格跳过；遇未翻开格翻开；邻雷数为 0 的入队继续
        - 洪泛中遇雷 → 按失败处理（3.3-b）
     c. 若 revealedCount === rows×cols − mines → status → 'won'，停止计时，胜利事件
```

### 3.3 Chord
```
输入 (r, c)
1. 前提：格子已翻开 且 neighborMines > 0
2. 统计周围旗数 flagAround
3. flagAround !== neighborMines → 无操作
4. flagAround === neighborMines → 对周围所有 state 为 hidden/question 的格子执行 3.2 的翻开逻辑
   （若期间命中雷 → 判负）
```

### 3.4 标记（toggleMark）
```
输入 (r, c)
1. 仅未翻开格子有效；已翻开或终态无操作
2. state 循环：hidden → flagged → question → hidden
3. flagCount 同步增减：hidden→flagged +1；flagged→hidden −1；question 不改变 flagCount
```

### 3.5 胜负判定
- 胜：`revealedCount === rows × cols − mines`（在 3.2/3.3 翻开后即时检查）。
- 负：翻开任意雷格（3.2/3.3 路径统一处理）。

### 3.6 计时器
- 存储 `startTime = Date.now()`；`elapsed = Date.now() − startTime`，格式化 `mm:ss`。
- UI 层用 `setInterval`（1s）触发重绘，但**显示值永远由时间差计算**，消除漂移。
- 上限 99:59，超过后定格显示 `99:59`。

## 4. 视图层（ui.js）设计

### 4.1 页面布局
```
┌──────────────────────────────────────────────┐
│ 标题「扫雷」+ 难度切换按钮组 + [🔊 静音开关]    │
├──────────────────────────────────────────────┤
│ [剩余雷数]  [😊表情]  [计时 mm:ss]            │   ← 状态栏
├──────────────────────────────────────────────┤
│            棋盘 (CSS Grid)                    │
├──────────────────────────────────────────────┤
│ 操作提示（左键翻开 / 右键标记…）              │
└──────────────────────────────────────────────┘
```

### 4.2 渲染策略
- 棋盘用 CSS Grid：`grid-template-columns: repeat(cols, var(--cell-size))`。
- 格子尺寸自适应：`--cell-size = min(42px, floor(可用宽/cols), floor(可用高/rows))`，可用空间取视口的 85%。
- 每次状态变更后全量重绘棋盘（≤2400 格，全量重绘性能可接受且逻辑简单；用 `innerHTML` 重建或 DOM 复用均可，选择**DOM 复用 + 类名切换**以保留动画）。

### 4.3 格子 DOM 与样式
- 每个格子为 `<button class="cell" data-r data-c>`。
- 状态类：`.hidden / .revealed / .flagged / .question`、`.mine-hit`（踩中的雷）、`.mine-shown`（失败后展示的雷）、`.flag-wrong`（错误旗）。
- 数字颜色按经典配色（1 蓝 / 2 绿 / 3 红 / 4 深蓝 / 5 棕 / 6 青 / 7 黑 / 8 灰）。

### 4.4 事件绑定
| 事件 | 行为 |
| --- | --- |
| 格子 `click` | 左键翻开（含首击、Chord）；成功后播放点击音效，胜利/失败播放对应音效 |
| 格子 `contextmenu` | 右键标记循环（`preventDefault` 屏蔽系统菜单）；切换成功播放标记音效 |
| 表情按钮 `click` | 重开当前难度 |
| 难度按钮 `click` | 切换难度并重开 |
| 「自定义」按钮 `click` | 打开对话框 |
| 静音按钮 `click` | 切换静音状态并更新图标 |
| 对话框「确定/取消」 | 校验并应用 / 关闭 |

### 4.5 状态栏
- 剩余雷数：三位显示（`padStart(3,'0')`，负数含 `-` 前缀，如 `-03`）。
- 计时：`mm:ss`。
- 表情：`😊 / 😎 / 😵` 三态切换；`title` 提示"重新开始"。

### 4.6 自定义对话框
- 原生 `<dialog>` 元素；三个 `<input type="number">`（行 / 列 / 雷数）。
- 校验逻辑与 FR-02 一致；错误信息以 `<p class="error">` 展示，不关闭对话框。

### 4.7 动画（CSS 实现，JS 仅切换类名）
| 场景 | 效果 |
| --- | --- |
| 翻开 | 轻微缩放+淡入（150ms） |
| 插旗 | 图标弹入（100ms） |
| 踩雷失败 | 踩雷格红色脉冲放大；其余雷格逐一显现（间隔 40ms，纯 CSS transition-delay） |
| 胜利 | 未标记雷自动补旗，棋盘轻微上浮+阴影柔和化 |
| 表情切换 | 轻微弹跳 |

## 6. 音效模块设计（audio.js）

### 6.1 目标
在零外部依赖约束下，用 Web Audio API 程序化合成全部音效（FR-14），并提供内存态静音开关（FR-15）。

### 6.2 对外 API（window.MINESWEEPER_AUDIO / module.exports）
| 方法 | 说明 |
| --- | --- |
| `playClick()` | 翻开/Chord 轻"嗒"声 |
| `playFlag()` | 右键标记切换轻"啵"声 |
| `playWin()` | 胜利喜庆音效 |
| `playLose()` | 踩雷遗憾音效 |
| `isMuted()` / `setMuted(v)` / `toggleMute()` | 静音状态读写与切换 |
| `_getScore(name)` | 测试钩子：返回指定音效的评分数据（纯数据，无副作用） |
| `_useContext(mock)` | 测试钩子：注入 mock AudioContext |

### 6.3 评分数据（Score，纯数据、可测试）
每条音效 = 音符数组 `[{ f, t, d, type, g, glideTo? }]`：
- `f` 起始频率 Hz；`t` 相对起点（s）；`d` 时长（s）；`type` 波形；`g` 峰值增益；`glideTo` 可选目标频率（滑音）。

| 音效 | 评分规格 |
| --- | --- |
| click | 900Hz 正弦 0.05s，增益 0.12（极短促） |
| flag | 650Hz 三角波 0.06s + 950Hz 三角波 0.06s（双音"啵"） |
| win | C5(523.25)→E5(659.25)→G5(783.99)→C6(1046.50) 三角波上行琶音，间隔 0.14s、尾音 0.5s 渐强收尾 |
| lose | 392→311→233Hz 三角波滑音三连下坠，每音 0.4~0.6s，低沉缓慢 |

### 6.4 音频上下文管理
- `AudioContext` **懒初始化**：仅在首次播放音效时创建（首次必然发生在用户手势内——格子点击，满足浏览器自动播放策略）。
- 创建时若 `state === 'suspended'` 则调用 `resume()`。
- 静音时不创建上下文（若已创建则直接跳过播放）。

### 6.5 播放实现
- 每个音符 = `OscillatorNode` + `GainNode`，起始增益指数上升（0.01s）、结束指数衰减，`osc.start(t)` / `osc.stop(t+d+0.05)`。
- 滑音音符用 `frequency.exponentialRampToValueAtTime(glideTo, ...)`。
- 播放函数在无 `AudioContext` 支持或静音时静默返回，绝不抛出。

### 6.6 与 UI 的接线（FR-14 / FR-15）
- `ui.js onCellClick`：`won → playWin()`；`lost → playLose()`；其余成功翻开/Chord → `playClick()`。
- `ui.js onCellContextMenu`：标记状态实际切换成功时 → `playFlag()`。
- 静音按钮（头部，`.mute-btn`）：点击 `toggleMute()`，图标 🔊/🔇 与标题"音效：开/关"同步更新。

## 7. 关键设计决策（ADR）

| 决策 | 理由 |
| --- | --- |
| core 用 UMD 导出 | 同一份逻辑同时服务浏览器与 Node 验收测试，无构建 |
| 布雷推迟到首击 | 满足 FR-03 首击安全且实现最简单（排除法） |
| 计时基于时间差 | 消除 setInterval 漂移（NFR 要求） |
| 全量重绘棋盘 | ≤2400 格 DOM 操作在现代浏览器 < 10ms，换取逻辑简单、动画可复用 |
| 不用 localStorage | 用户明确排除最佳成绩功能，保持零副作用 |
| 音效用 Web Audio 合成 | 满足零外部依赖约束；无需音频文件与网络资源；评分数据纯函数化，可在 Node 中验收 |
| 静音不持久化 | 用户确认仅内存态；避免引入存储副作用 |
